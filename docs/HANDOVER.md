## 三、日常怎麼用

### 每天排班

1. 開網頁 →「📅 產生班表」→ 選日期 → **🔍 預覽**（不會紀錄，可以一直按）
2. 沒問題 → **✅ 確定紀錄**
3. 「📝 文字班表」→ 複製 →貼到 LINE 群組
4. 「☁️ 雲端同步」上傳，LINE bot 才會回到最新的

> 已經確定紀錄過的日子按「重排這天」會用最新規則重算並覆蓋，次數不會疊加。

### 已經公布出去的班表要保住

「產生班表」頁面 →「🔒 鎖定這天」→ 把當初貼到群組的文字班表整段貼回去。
之後改規則、改名冊都不會動到它，次數照樣算。

### 派採買／掃廁所

「🛒 採買・掃廁所」分頁 → 展開那一天 → 採買打勾（可多人）、掃廁所下拉選一位。

- 採買勾到的人**那天早餐、中餐完全不排**，晚上才歸隊
- 掃廁所是 0900＋2100 同一位包辦，**不影響他當天其他勤務**
- 8/7～8/14 的掃廁所已經預先填上愷宸

### 改名冊

「👥 名冊」分頁可以改：加入／離開日期與方式、免排項目、固定勤務、打菜固定角色、固定送便當。
**改完會自動重播所有已排的日子。**

> 三餐勤務停用之後，名冊上那些「固定勤務／打菜角色／送便當」暫時沒有作用（那幾項程式不排了），
> 但欄位留著，旗標一打開就會生效。

### 班長貼每日通知（LINE）

班長把**熱追／便當數量／行動準據**貼在群組裡，機器人會自動解析、照日期存到雲端，
不用叫它、也不用有「勤務」兩個字。

- 標題自己會帶日期：「明日三餐熱追」「8/8便當數量」「@All 8/8行動準據」都認得
- **前一天貼明天的**、**當天貼今天的**都可以（會用收到訊息的時間去推）
- 同一天再貼一次就**覆蓋掉**那幾段，沒重貼的段落保留
- 存好之後機器人會回一句確認，寫清楚存了哪一天的哪幾段
- 之後 **@機器人** 就會回六張卡片

> 存在 Firestore 的 **`briefings/{房間代碼}`**，跟名冊那份（`rosters/{房間代碼}`）**是兩份不同的文件**。
> 分開存是為了不讓機器人跟網頁 App 互相蓋掉——App 是整份 state 一次覆蓋的。

## 五、部署

### GitHub Pages（網頁）

- 從 `claude/new-repo-init-l5ckx3` 分支自動部署
- **repo 裡沒有 `.github/workflows`**，那個 `pages build and deployment` 是 GitHub 自動產生的
- 偶爾會失敗（`The job was not acquired by Runner of type hosted` / `Internal server error`）——那是 **GitHub 自己沒有 runner**，不是程式問題。`runner_id: 0` 就是證據。重跑就好

### Vercel（LINE bot）

`vercel.json` 已設好，重點是 `"includeFiles": "js/**"`——serverless function 需要 `js/` 底下那份排班程式碼。

需要的環境變數：

| 變數 | 用途 |
|---|---|
| `LINE_CHANNEL_SECRET` | 驗簽章 |
| `LINE_CHANNEL_ACCESS_TOKEN` | 回訊息 |
| `FIREBASE_API_KEY` / `FIREBASE_PROJECT_ID` / `ROSTER_ROOM_CODE` | 讀雲端狀態 |
| `STATE_READ_KEY` | 「看完整」網頁模式的金鑰 |
| `LIFF_ID` / `LIFF_CHANNEL_ID` | （選用，目前沒用）LIFF 模式 |
| `PUBLIC_BASE_URL` | （選用）圖片網址的網域 |

> ⚠️ Vercel 的 **Deployment Protection** 打開的話 LINE webhook 會拿到 401，要關掉或加 bypass。

### Firebase

匿名登入 + Firestore，兩份文件：

| 文件 | 誰寫 | 內容 |
|---|---|---|
| `rosters/{房間代碼}` | 網頁 App | 整份 state（名冊、班表、次數…）以 JSON 字串存在單一欄位 |
| `briefings/{房間代碼}` | **LINE bot** | 班長貼的熱追／便當數量／行動準據，照日期存 |

**兩份一定要分開**：App 是整份 state 一次覆蓋的，機器人如果寫同一份，
值星按「確定紀錄」的同時班長剛好貼準據，其中一邊就會被蓋掉。

（Firestore 不支援巢狀陣列，所以兩份都是存 JSON 字串。）

⚠️ **Firestore 規則要補一段**：原本只有 `match /rosters/{roomId}`，
機器人存班長通知會被擋下來（權限不足）。到 Firebase 主控台 → Firestore → 規則加上：

```
match /briefings/{roomId} {
  allow read, write: if request.auth != null;
}
```
