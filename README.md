# 🍚 值星公差小幫手 (mess-duty-roster-for-army)

專為 261 梯／263 梯設計的公平自動排勤務工具。純前端（HTML/CSS/JS，無框架、無建置流程），資料存在瀏覽器 `localStorage`，開啟 `index.html` 即可使用。這次勤務期間為 **2026/08/01 ～ 2026/08/14**。

## 涵蓋的勤務規則

- **洗碗**（每餐固定人數，預設6人）：261 洗碗池（排除固定送便當的7、8號）與263 洗碗池，每天輪流當「起始梯」，起始梯用持續指標往下輪，次要梯每次從頭排，讓每天需要重複洗兩次碗的人也公平輪替。
- **廚餘／包便當袋子／擦桌子／清地板收垃圾**：排除當餐洗碗與固定送便當人員後，依「該項勤務累計次數少者優先，同次數依 261→263、序號」分配。
- **抬便當上車／抬便當上樓**：除了當餐洗碗的人以外，在場的人全部一起幫忙（含固定送便當的兩位）。兩者人選相同，顯示時合併成一行。
- **幫忙包便當**：除了當餐洗碗的人與固定送便當的兩位以外，其他人做完自己的事都要去幫忙包便當，所以個人分工會出現「廚餘／包便當」這種組合，被排到包便當袋子的人則是「包便當／抬上車／抬上樓」。
- **抬洗衣籃上來（下午）／抬洗衣籃下去（睡前）**：各2人，18人依名冊順序兩人一組往下輪（送便當的兩位也要輪）。今天睡前抬下去的那組，下一個排班日負責抬上來，所以不需要另外排。輪替從 2026/08/02 開始，第一天只有抬下去。進度是記「上一組最後一位是誰」而不是名冊位置，這樣有人退伍時才不會跳過還沒輪到的人。
- **送便當**：固定2人（預設261的7、8號）。此人退伍時會跳出提醒，需在名冊手動指定新人選。
- **撤收**：每天把可排撤收的人**剛好分完**到早、中、晚，所以每人每天固定做一次撤收。人數是早上最輕鬆，16人時為 **早4／中6／晚6**（人數變少時按同比例縮減）。**固定送便當的兩位不排撤收**。公平性靠「每個人在各餐別的撤收次數」平衡，次數少的優先被排到那一餐，不會有人固定只做早餐或只做晚餐。採買的人早、中不在，會直接安排到晚上撤收。
- **採買**：週一～週四固定各一位（預設 週一呂胤玄、週二林柏翰、週三陳柏翰、週四陳俊穎），集合時間預設 週一三 0600、週二四 0450，都可在「採買」分頁改。**採買的人當天早餐、中餐完全不排勤務（含撤收），晚餐才歸隊**，因此那兩餐的包便當袋子會自動少一位，人數才對得起來。集合時間會印在文字班表上。如果那天輪到的人已經退伍，產生班表時會跳提醒。
- **人數縮減**：可在「勤務設定」頁調整「現有人數 → 各勤務人數」對照表，退伍人數減少時自動套用對應人數；若人數超出表格範圍會提示補上設定。
- **退伍**：可在名冊直接填入每個人的退伍日期（可預先填未來日期）。產生某一天的班表時，只要那天已經到或過了退伍日，該員就會自動排除在外，不需要每天手動切換狀態。

## 先預覽、按確定才會記錄

「產生班表」分成兩步，避免測試時不小心污染公平次數：

1. **🔍 預覽**：只是計算給你看，不會寫入任何次數或狀態，可以重複按著玩。
2. **✅ 確定紀錄**：把結果真正存起來，這時才會累計洗碗/廚餘/…等次數、推進洗碗與撤收的輪值指標。

如果想全部歸零重來，到「名冊」頁面按「🔄 重置所有勤務紀錄」，次數、班表、輪值指標都會清空（人員名單與採買星期表保留）。

## 同一天永遠排出同一份班表

班表不是一天一天累加出來的，而是從「已確定的日期清單」配上名冊與各項設定**重播**推導出來的：每次有任何變動（包括改採買星期表、改退伍日期），系統都會依日期順序把所有已確定的日子重算一遍。因此

- 同一天不管重排幾次，只要名單與勤務設定沒變，結果一定一模一樣；
- 「重排這天」會自動清掉那天原本的結果再重算，不會殘留舊資料，也不會重複累計次數；
- 「預覽」看到的內容跟之後「確定紀錄」的結果保證一致；
- 可以「取消這天的紀錄」，之後再排回來還是同一份班表。

## 頁面

- 📅 產生班表：選日期預覽/確定當天班表（預設分頁）
- 📝 文字班表：可直接複製貼到群組的純文字班表，分「依餐別」與「依個人」兩種版面，不含任何 emoji
- 👥 名冊：新增/編輯人員、設定退伍日期、指定固定送便當人員、重置勤務紀錄
- ⚙️ 勤務設定：人數縮減對照表（可自行新增/調整/刪除）
- 🛒 採買：設定週一～週日各由誰採買與集合時間（可留空）、查看累計次數
- 📊 公平性總覽：每項勤務一個圓餅圖
- ☁️ 雲端同步：接上自己的 Firebase，把資料備份到雲端、換裝置時拉回來

文字班表裡的姓名預設只顯示後兩個字（例如「李愷宸」顯示「愷宸」），如果兩個人的後兩字重複（目前是261的陳柏翰與263的林柏翰），就會自動改顯示全名以區分。

## 公平性總覽怎麼看

每項勤務一個圓形圖，**每個人固定佔一格**（角度都一樣，依名冊順序排），格子**往外伸得越長＝做越多次**（面積正比於次數）。淺色底代表那一格還是空的，也就是這個人還沒輪到。

之所以不用「照比例切派」，是因為次數 0 的人在比例派裡角度是 0、根本畫不出來——勤務還沒輪完一圈時（例如第一天擦桌子只有3人次），圖上就只會出現3塊，看不到其他人。改成等角度之後，全部 16／18 個人永遠都在圖上。

顏色不是用來區分18個人（18種顏色沒有人分得出來），而是拿他的次數跟**公平範圍**比：深藍「明顯偏少」→ 淺藍「略少」→ 灰「接近平均」→ 橘「略多」→ 深橘紅「明顯偏多」。**整張圖越接近灰色、長度越整齊，就代表這項勤務分配得越平均。**

「公平範圍」是總人次除以應分擔人數的整數區間。例如擦桌子一天只有3個名額，5天下來15人次要分給16個人，那每人拿 0 次或 1 次都算公平，拿到 2 次才算偏多——用區間而不是「跟平均值的比例」，才不會在勤務還沒輪完一圈時把所有做過的人都誤判成偏多。固定送便當的兩位不會被排到洗碗、雜項勤務與撤收，計算時會排除，免得他們的 0 次被當成偏少；洗衣籃則是全員一起輪，不排除。

配色是 diverging（雙向）色階，已用色盲模擬驗證過相鄰色差（CVD ΔE 17.9、一般視覺 ΔE 18.1，皆通過門檻）。每張圖旁邊都有完整的次數/佔比表格，滑鼠移到扇形上也會顯示明細，不會只靠顏色傳達資訊。

## 雲端同步（選用）

預設資料只存在瀏覽器的 localStorage，清快取或換手機就會不見。「☁️ 雲端同步」分頁可以接上**你自己的 Firebase 專案**，把資料自動備份到雲端，換裝置時填一樣的房間代碼就能整份拉回來，手機和電腦也能看同一份。

設定步驟（分頁裡也有同一份說明和可複製的規則）：

1. 到 [Firebase 主控台](https://console.firebase.google.com/) 免費建一個專案。
2. 新增一個「網頁應用程式」，把它給的 `firebaseConfig` 整段貼進設定框（支援直接貼 `const firebaseConfig = {...};`）。
3. **Build → Firestore Database** 建立資料庫。
4. **Build → Authentication → Sign-in method** 啟用**匿名**登入。
5. 把 Firestore 規則換成：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rosters/{roomId} {
      allow read, write: if request.auth != null;
    }
  }
}
```

運作方式：localStorage 仍是主要儲存（離線照常可用），雲端只是鏡像；有變更就延遲 1.5 秒自動上傳，其他裝置透過 `onSnapshot` 即時收到。整份狀態以 JSON 字串存在 `rosters/{房間代碼}` 的單一欄位裡（Firestore 不支援巢狀陣列，直接存物件會有相容性問題）。衝突以最後寫入者為準，畫面會顯示雲端最後更新時間讓你判斷該上傳還是下載。Firebase 設定與房間代碼存在另一個 localStorage key，不會被同步覆蓋，也不會出現在匯出的備份檔裡。

> ⚠️ **安全性**：上面那組規則的意思是「任何登入過的人都能讀寫任何房間」。因為名冊裡有真實姓名，請用分頁裡的「隨機產生」按鈕產一組不好猜的房間代碼並**當成密碼看待**，不要用 `test` 這種。知道代碼的人就能看到、改到你的班表。

沒設定雲端同步的話 App 一樣能正常使用，只是沒有雲端備份；頁腳的「匯出備份／匯入備份」隨時可以另外存一份 JSON 檔。

## 使用方式

直接用瀏覽器開啟 `index.html`，或用任何靜態網頁伺服器（例如 `npx serve .` / `python3 -m http.server`）啟動後瀏覽。頁腳有「匯出備份／匯入備份」可用 JSON 檔備份或轉移資料。
