## 三、日常怎麼用

### 每天排班

1. 開網頁 →「📅 產生班表」→ 選日期 → **🔍 預覽**（不會紀錄，可以一直按）
2. 沒問題 → **✅ 確定紀錄**
3. 「📝 文字班表」→ 複製 →貼到 LINE 群組
4. 「☁️ 雲端同步」上傳，LINE bot 才會回到最新的

> 已經確定紀錄過的日子按「重排這天」會用最新規則重算並覆蓋，次數不會疊加。

### 已經公布出去的班表要保住

「產生班表」頁面 →「🔒 鎖定這天」→ 把當初貼到群組的文字班表整段貼回去。
之後改規則、改名冊都不會動到它，次數照樣算。

### 派採買／掃廁所

「🛒 採買・掃廁所」分頁 → 展開那一天 → 採買打勾（可多人）、掃廁所下拉選一位。

- 採買勾到的人**那天早餐、中餐完全不排**，晚上才歸隊
- 掃廁所是 0900＋2100 同一位包辦，**不影響他當天其他勤務**
- 8/7～8/14 的掃廁所已經預先填上愷宸

### 改名冊

「👥 名冊」分頁可以改：加入／離開日期與方式、免排項目、**固定勤務**（早晚洗碗＋中午廚餘／三餐都洗碗）、抬便當分組、打菜固定角色、固定送便當。
**改完會自動重播所有已排的日子。**

## 四、下一步要做的事（使用者已經提過）

> ⚠️ 以下都**還沒做**，是使用者預告的下一輪需求。動手前先跟他確認細節。

### 1. LINE 多一組卡片：熱食追加／準據／便當數量

使用者原話：

> 希望 line 可以回覆另一類卡片系列像是熱追 準據 便當數量都希望可以呈現，然後還要呈現整體打菜流程

**「整體打菜流程」已經做了**——就是現在卡片的第一張（`flowBubble()`，內容在 `js/state.js` 的 `MEAL_FLOW`）。剩下三項還沒做。

**要做的**：新增一組卡片（跟現有的「勤務卡片」並列，用不同指令觸發，例如「今日便當」「今日數量」）。

**動手前要問清楚**：

- 「熱追」＝熱食追加？「準據」＝準據表？這些數字是**每天不一樣、要人工輸入**，還是**從人數算出來**的？
- 便當數量是各連的數量嗎？要不要分早／中／晚？
- 資料從哪來——新增一個分頁讓他輸入，還是從現有資料推？

**技術面**：`api/_lib/cards.js` 已經是「一個 section 一段」的結構，加新卡片不難（流程卡就是這樣加的）；指令解析在 `api/_lib/parseCommand.js`，目前只認「勤務／班表」和 @機器人。加新指令記得**新卡片的顏色要進 `scripts/check-card-colors.js` 的 `CARDS`**，相鄰 ΔE 要 ≥ 20。

### 2. 排勤務的 UI/UX 太雜，要優化

使用者原話：

> 就是優化目前排勤務的 UIUX 目前太雜了

**現況**：「📅 產生班表」一頁塞了選日期、預覽、確定紀錄、重排、取消紀錄、鎖定這天（可展開的貼上區）、警告區、三張餐別卡片＋全日卡片。餐別卡片改成五段式之後**又更長了**。

**可以考慮的方向**（沒跟他確認過，先別動手）：

- 三餐改成分頁籤，不要一次全部展開
- 「鎖定這天」收進次要選單，那是偶爾才用的功能
- 手機上一屏只看得到一點點內容，可能要摺疊「前置」這種固定不變的段落
- 七個分頁對手機來說也偏多，也許可以合併

**動手前一定要問他「哪裡覺得雜」**，不要自己猜。

### 其他他說「可能還有」

## 五、部署

### GitHub Pages（網頁）

- 從 `claude/new-repo-init-l5ckx3` 分支自動部署
- **repo 裡沒有 `.github/workflows`**，那個 `pages build and deployment` 是 GitHub 自動產生的
- 偶爾會失敗（`The job was not acquired by Runner of type hosted` / `Internal server error`）——那是 **GitHub 自己沒有 runner**，不是程式問題。`runner_id: 0` 就是證據。重跑就好

### Vercel（LINE bot）

`vercel.json` 已設好，重點是 `"includeFiles": "js/**"`——serverless function 需要 `js/` 底下那份排班程式碼。

需要的環境變數：

| 變數 | 用途 |
|---|---|
| `LINE_CHANNEL_SECRET` | 驗簽章 |
| `LINE_CHANNEL_ACCESS_TOKEN` | 回訊息 |
| `FIREBASE_API_KEY` / `FIREBASE_PROJECT_ID` / `ROSTER_ROOM_CODE` | 讀雲端狀態 |
| `STATE_READ_KEY` | 「看完整」網頁模式的金鑰 |
| `LIFF_ID` / `LIFF_CHANNEL_ID` | （選用，目前沒用）LIFF 模式 |
| `PUBLIC_BASE_URL` | （選用）圖片網址的網域 |

> ⚠️ Vercel 的 **Deployment Protection** 打開的話 LINE webhook 會拿到 401，要關掉或加 bypass。

### Firebase

匿名登入 + Firestore，整份狀態以 JSON 字串存在 `rosters/{房間代碼}` 的單一欄位。
（Firestore 不支援巢狀陣列，直接存物件會有相容性問題。）
